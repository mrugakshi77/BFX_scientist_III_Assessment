# Multiomic cancer-panel assignment

A leakage-safe, reproducible discovery-to-panel workflow for the supplied synthetic cfDNA + protein data. The two-page write-up is in [REPORT.md](REPORT.md).

## Repository layout

```
./
├── multiomic_panel/        pipeline package (workflow + CLI)
├── tests/                  guardrail tests
├── results/                final panel + locked-holdout metrics (regenerated by `pixi run analysis`)
├── config.yaml             tunable settings (seed, fold counts, missingness threshold, feature prefixes)
├── pixi.toml / pixi.lock   environment and tasks
├── REPORT.md               two-page write-up
└── Candidate_Assignment_Multiomic_Panel.docx   original prompt
```

The raw data is **not** committed. Place the five CSVs at `./candidate_assignment_data/candidate_data/` (same layout as the assignment zip) before running.

## Setup

Install [pixi](https://pixi.sh) once (it manages the pinned conda-forge environment):

```
# Linux / macOS
curl -fsSL https://pixi.sh/install.sh | sh

# Windows PowerShell
iwr -useb https://pixi.sh/install.ps1 | iex
```

Then from the repo root:

```
pixi run analysis   # end-to-end pipeline → results/
pixi run test       # four guardrail tests
```

The first run resolves and caches the environment (~1–2 min); subsequent runs are instant.

## Design choices (short)

- All evaluation uses `StratifiedGroupKFold` grouped by `patient_id`; no patient's draws can occur in both training and test.
- Imputation, missingness filtering, scaling, univariate screening, and regularized model tuning fit **only inside each training fold**.
- Protein features are **plate-median centered** using per-plate medians learned on the training fold only (plates unseen in training fall back to the training global median).
- Protein models use the protein-available subset. A matched methylation+fragmentomics model runs on that same subset so protein's incremental value is interpretable.
- The final 5+3 panel is selected only in a development subset; its headline score comes from a patient-grouped holdout untouched by panel selection.
- Stage is excluded from prediction and retained only for QC summaries.
- Repeats and extreme GC are **reported as ddPCR feasibility flags**, not treated as automatic exclusions.

## Outputs

Everything in `results/` is regenerated deterministically by `pixi run analysis`. Committed:

- `results/panel/methylation_panel_with_feasibility.csv` and `protein_panel.csv` — the locked 5+3 panel.
- `results/panel/restricted_final_panel_locked_holdout_metrics.csv` — the headline result.
- `results/panel/restricted_final_panel_locked_holdout_predictions.csv` and `restricted_final_panel_development_oof_predictions.csv` — per-sample predictions, so AUC/AP can be recomputed independently.
- `results/study_partitions.csv` — which samples went into development vs the locked holdout.

QC tables, per-modality development CV outputs, and panel-selection intermediates are generated on each run but intentionally not committed.
